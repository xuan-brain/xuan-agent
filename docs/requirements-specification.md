## 1. 项目概述
### 1.1 项目背景与目标
科研工作者在文献管理与学术写作过程中面临诸多痛点：文献数量爆炸式增长导致检索效率低下，跨数据库检索割裂，文献阅读理解耗时巨大，学术写作缺乏系统性辅助，基金申请书等结构化文档撰写负担沉重。本项目旨在构建一个基于Rust和Rig框架的科研AI Agent（XuanAgent），通过模块化、可扩展的架构，结合Model Context Protocol（MCP）协议，优先复用成熟开源解决方案，为科研人员提供从文献发现、阅读、整理到论文、基金、书籍撰写的一站式智能辅助平台。
**核心目标**：
- 将科研人员从繁琐的文献管理与基础写作工作中解放出来，提升科研效率
- 构建可自托管、可扩展、尊重数据隐私的科研AI基础设施
- 建立模块化的MCP生态，便于社区贡献与能力扩展
### 1.2 目标用户画像
| 用户类型 | 特征描述 | 核心需求 |
|----------|----------|----------|
| **研究生** | 文献阅读量大、写作经验不足、时间压力巨大 | 快速理解文献、生成综述、论文结构辅助、语言润色 |
| **高校教师** | 科研与教学并重、项目申请频繁、需要管理团队文献库 | 项目基金撰写、团队文献库共享、高级写作指导 |
| **科研院所研究员** | 专职科研、项目周期长、需要深度文献分析 | 深度文献挖掘、研究趋势分析、长期知识管理 |
| **跨学科研究者** | 需要涉猎多个领域、文献跨度大 | 跨领域文献整合、术语解释、研究方法对比 |
## 2. 功能需求
### 2.1 文献发现与获取模块
#### 2.1.1 多源统一检索
- **需求描述**：提供统一的检索接口，同时查询本地文献库与外部学术数据库。
- **功能要求**：
  - 支持数据源：本地文献库（如 Zotero、EndNote、Mendeley 等）、Semantic Scholar、PubMed、Crossref、arXiv等
  - 检索方式：关键词检索、语义检索（基于向量相似度）、组合检索
  - 过滤条件：年份范围、期刊/会议、引用次数、作者、研究类型
  - 检索结果统一展示，标明来源，支持一键导入本地库
#### 2.1.2 智能文献获取
- **需求描述**：自动获取检索到文献的全文PDF。
- **功能要求**：
  - 优先通过开放获取版本（Unpaywall-like接口）获取
  - 支持机构订阅认证（需用户配置代理或认证信息）
  - 批量下载任务队列，断点续传，失败重试
  - 遵守各平台的robots.txt和请求频率限制
### 2.2 文献阅读与理解模块
#### 2.2.1 单篇文献深度分析
- **需求描述**：对单篇PDF文献进行结构化解析与智能解读。
- **功能要求**：
  - 结构化摘要：自动提取研究问题、方法、实验、结果、创新点、局限性
  - 关键概念解释：识别并解释专业术语、缩写、公式
  - 图表解读：解析图表含义，用自然语言描述图表信息
  - 引用分析：识别关键引用，构建引用网络
#### 2.2.2 多篇文献综合处理
- **需求描述**：对多篇相关文献进行比较、综合与综述生成。
- **功能要求**：
  - 方法对比表：自动生成不同文献中方法、数据集、指标的对比表
  - 研究演进分析：按时间线展示研究主题的演进过程
  - 综述生成：根据选定文献集合，生成结构化综述草稿（引言、主体、结论）
  - 争议点识别：识别不同文献间的观点冲突与争议焦点
#### 2.2.3 文献阅读MCP（mcp-server-literature-reading）
- **职责边界**：专注于文献内容的检索、阅读、理解与标注，不涉及写作生成。
- **核心工具**：
  - `literature_search`：多源文献检索
  - `get_paper_fulltext`：获取文献全文内容
  - `summarize_paper`：生成结构化摘要
  - `compare_papers`：多篇文献对比分析
  - `extract_key_entities`：提取关键实体（方法、数据集、指标）
- **资源提供**：
  - `library://local`：本地文献库访问（支持 Zotero、EndNote、Mendeley 等多种文献管理工具）
  - `paper://pdf/{item_key}`：单篇PDF全文内容
  - `annotation://list/{item_key}`：文献标注列表

**说明**：XuanAgent 设计为通用的科研助手，可以与多种文献管理工具集成。Zotero 仅作为开发测试的示例实现，用户可以根据需要集成其他文献管理工具（如 EndNote、Mendeley、Papers 等）。
### 2.3 文献整理与知识管理模块
#### 2.3.1 自动分类与标签系统
- **需求描述**：利用AI自动对文献进行分类与打标签。
- **功能要求**：
  - 预设分类体系：研究类型（方法、应用、综述）、研究领域（CS、Biology等）、研究阶段（概念、实证、评审）
  - 自动标签：基于内容分析自动生成标签，如“深度学习”、“医学影像”、“COVID-19”
  - 用户自定义标签体系，支持层级标签
  - 标签置信度展示，用户可调整或确认
#### 2.3.2 文献知识库构建
- **需求描述**：将文献内容转化为可检索、可关联的知识库。
- **功能要求**：
  - 文献切片：将PDF/Word文档按语义单元切片（章节、段落）
  - 向量化存储：使用 SurrealDB 存储嵌入向量
  - 知识图谱：构建实体关系图（作者-机构-方法-应用场景）
  - 智能检索：支持自然语言查询，返回相关文献片段及关联文献
### 2.4 学术写作辅助模块
#### 2.4.1 论文写作辅助
- **需求描述**：提供论文各部分的写作指导与生成。
- **功能要求**：
  - **研究问题生成**：根据领域热点与研究空白，生成可行的研究问题
  - **文献综述撰写**：基于文献阅读MCP提供的材料，生成综述段落并自动插入引用
  - **结构化大纲生成**：为论文各部分（引言、方法、结果、讨论）生成详细大纲
  - **段落生成与润色**：根据大纲和文献材料，生成段落初稿，并提供润色建议
  - **语言检查**：语法纠正、学术风格优化、术语一致性检查
#### 2.4.2 基金申请书撰写
- **需求描述**：辅助科研人员撰写结构化的基金申请书。
- **功能要求**：
  - **模块化生成**：针对NSFC等基金模板，生成各模块内容：
    - 研究背景与意义
    - 研究内容与目标
    - 研究方法与技术路线
    - 创新点与特色
    - 预期成果
    - 研究基础与团队
  - **评审模拟**：模拟同行评审过程，对申请书进行评分与修改建议
  - **文献支持**：自动插入相关文献引用，支持引用格式定制
#### 2.4.3 书籍与报告撰写
- **需求描述**：辅助长篇内容（书籍、技术报告）的撰写。
- **功能要求**：
  - 章节结构规划：根据主题生成合理的章节划分与大纲
  - 内容扩展：将章节大纲扩展为完整内容
  - 术语管理：维护术语表，确保全书术语一致性
  - 交叉引用管理：自动处理章节间的交叉引用
#### 2.4.4 学术写作MCP（mcp-server-academic-writing）
- **职责边界**：专注于文本文档的生成、修改与评审，不直接管理文献库。
- **核心工具**：
  - `draft_section`：根据大纲生成章节内容
  - `improve_text`：文本润色与改写（多种风格、多种模式）
  - `check_logic`：逻辑连贯性检查
  - `generate_references`：参考文献列表生成
  - `review_proposal`：基金申请书评审模拟
- **资源提供**：
  - `document://current`：当前工作文档内容
  - `template://nsfc`：基金申请书模板
  - `style://ieee`：学术写作风格指南
### 2.5 用户界面与交互需求
#### 2.5.1 聊天交互界面
- **需求描述**：提供基于对话的交互界面，作为用户与 Agent 交互的唯一入口。
- **功能要求**：
  - 多会话管理：每个研究项目/论文独立会话
  - 上下文保持：对话中保持文献与写作上下文
  - 可视化引用：AI回复中的引用可点击跳转原文
  - 历史记录：完整对话历史可搜索、可导出
  - 流式响应：支持实时流式输出，提升用户体验

**说明**：本项目专注于 Agent 后端和 MCP 服务器的实现，仅提供基础的聊天交互界面。完整的 Web 应用界面（如文献库管理、PDF阅读器、写作工作台等）和编辑器插件（如 VS Code、Obsidian 插件）将在其他独立项目中实现，通过调用本项目提供的 API 进行集成。

## 3. 技术架构需求
### 3.1 整体架构设计

本项目采用分层架构设计，专注于 Agent 后端和 MCP 服务器的实现。架构分为四个核心层次：

**架构层次说明**：
1. **Agent核心层**：基于 Rust + Rig 框架，实现 Agent 的核心逻辑，包括工作流引擎、记忆管理和工具调度
2. **MCP协议层**：实现 MCP Host 和多个 MCP Server，提供标准化的工具和数据访问能力
3. **数据与存储层**：集成 Zotero 文献库、SurrealDB 向量数据库、外部 API 和本地文件系统
4. **模型服务层**：通过 Rig 框架提供统一的 LLM 接口，支持 OpenAI、Anthropic 和本地模型

### 3.2 技术栈选型

本项目采用 Rust 生态系统构建，优先选择性能优异、内存安全的解决方案：

| 技术组件 | 选型方案 | 选型理由 |
|----------|----------|----------|
| **核心框架** | Rust + Rig | 高性能、内存安全，Rig提供LLM应用统一抽象 |
| **协议层** | MCP (Model Context Protocol) | 官方标准协议，社区生态丰富，支持多语言SDK |
| **文献管理集成** | Zotero MCP + PapersGPT | 成熟开源方案，已实现文献库访问与PDF对话 |
| **向量存储** | SurrealDB | 支持向量索引，多模态数据存储，嵌入式部署 |
| **PDF处理** | Pdfium/MuPDF | 高性能PDF渲染与文本提取 |
| **API框架** | Axum | 高性能异步Web框架，类型安全 |
| **聊天界面** | CLI (命令行界面) | 提供基础的交互能力，完整前端在其他项目实现 |

**技术选型原则**：
- **性能优先**：选择 Rust 生态中性能最优的方案
- **复用优先**：优先集成成熟的开源 MCP 服务器
- **标准协议**：采用 MCP 标准协议，确保生态兼容性
- **简洁实用**：避免过度设计，专注于核心功能
### 3.3 核心模块划分

项目采用模块化设计，各模块职责清晰，便于维护和扩展：

```
xuan-agent/
├── core/                    # 核心业务逻辑
│   ├── agent.rs            # Agent主循环与工作流
│   ├── memory.rs           # 记忆管理
│   ├── planner.rs          # 任务规划器
│   └── tools/              # 内置工具实现
├── mcp/                     # MCP协议实现
│   ├── host/               # MCP客户端
│   ├── servers/            # MCP服务器实现
│   │   ├── literature/    # 文献阅读MCP
│   │   └── writing/       # 学术写作MCP
│   └── protocol/           # 协议定义
├── rag/                     # 检索增强生成
│   ├── embedding/          # 向量化模块
│   ├── retrieval/          # 检索模块
│   └── rerank/             # 重排序模块
├── integrations/            # 第三方集成
│   ├── zotero/            # Zotero集成
│   ├── semantic_scholar/  # Semantic Scholar API
│   └── llm/               # LLM提供商集成
├── api/                     # Web API (供外部项目调用)
│   ├── routes/            # API路由
│   ├── models/            # 数据模型
│   └── middleware/        # 中间件
└── cli/                     # 命令行界面
    └── chat.rs            # 简单的聊天交互界面
```

**模块职责说明**：
- **core**: Agent 的核心逻辑，包括任务规划、记忆管理和工具调度
- **mcp**: MCP 协议的实现，包括 Host 和多个 Server
- **rag**: 文献的向量化、检索和重排序功能
- **integrations**: 第三方服务的集成，如 Zotero、Semantic Scholar 等
- **api**: 为外部项目（如 Web 前端、编辑器插件）提供 HTTP API
- **cli**: 提供基础的命令行交互界面
## 4. 非功能需求
### 4.1 性能需求
- **响应时间**：普通查询响应时间 < 3秒，复杂文献分析 < 30秒
- **吞吐量**：支持至少100并发用户操作
- **容量要求**：单用户支持管理100,000+文献记录
- **资源消耗**：内存占用 < 2GB（空闲状态），CPU占用 < 30%（平均负载）
### 4.2 安全需求
- **数据隐私**：所有用户数据本地存储，支持完全离线部署
- **API安全**：API接口支持基本的认证机制（如API Key）
### 4.3 可用性与可靠性
- **系统可用性**：99.9%可用性目标
- **错误恢复**：服务崩溃后自动恢复，不丢失用户数据
- **容错设计**：关键组件冗余部署，故障自动转移
- **监控告警**：系统运行状态实时监控，异常情况及时告警
### 4.4 可扩展性
- **MCP生态扩展**：支持集成更多开源MCP服务器
- **插件架构**：支持第三方插件扩展功能
- **协议兼容**：兼容MCP协议演进，支持新版本平滑升级
### 4.5 易用性
- **学习曲线**：新用户30分钟内掌握基本功能
- **帮助系统**：上下文帮助、视频教程、交互式引导
- **国际化**：支持中文、英文等多语言交互
- **API文档**：提供完整的 API 文档，方便其他项目集成
## 5. 实施计划与里程碑
### 5.1 分阶段实施路线
#### 阶段一：基础平台搭建（1-3个月）
- **目标**：建立核心Agent框架与MCP基础生态

  - Rust+Rig核心框架搭建
  - MCP Host实现，接入现有开源MCP服务器
  - 文献检索与基础阅读功能
  - 基础聊天交互界面
#### 阶段二：文献智能处理（2-4个月）
- **目标**：完善文献阅读与知识管理能力
- **关键交付物**：
  - 文献阅读MCP完整实现
  - 向量知识库构建
  - 文献自动分类与标签系统
  - 多篇文献综合分析功能
#### 阶段三：写作辅助系统（2-4个月）
- **目标**：实现学术写作辅助核心功能
- **关键交付物**：
  - 学术写作MCP实现
  - 论文各部分生成功能
  - 基金申请书撰写模块
  - API 接口完善与文档编写
#### 阶段四：优化与生态扩展（持续）
- **目标**：性能优化与社区生态建设
- **关键交付物**：
  - 性能优化与压力测试
  - 第三方MCP服务器兼容认证
  - 开发者文档与SDK
  - 社区运营与推广

## 6. 开源策略与合规要求
### 6.1 开源组件使用策略
| 组件类型 | 选择策略 | 优先级 |
|----------|----------|--------|
| **文献管理MCP** | 直接复用Zotero MCP、PapersGPT | 高 |
| **学术写作参考** | 参考Academic-Writing-Assistant、CoachGPT设计思路 | 中 |
| **PDF处理** | 基于开源库深度定制 | 中 |
### 6.2 许可证选择
- **核心代码**：采用双许可证策略：社区版AGPLv3，商业版商业许可证
- **MCP服务器**：MIT许可证，鼓励社区贡献
- **文档与教程**：CC BY-SA 4.0
### 6.3 社区治理
- **贡献指南**：明确的代码贡献流程、代码规范
